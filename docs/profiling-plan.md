# 当前硬件性能摸底计划

目标平台为 `8×A100-SXM4-80GB / NVSwitch`。全部推理测试、PPL、GPQA 和压力测试使用 `127.0.0.1:6688`。先完成 1M / 0.90 的完整基准，再单独核对 chunk 候选，随后完成上下文与显存水位矩阵；最终在选出的配置上运行一次 GPQA 和一次 30 分钟压力测试。

## 输入与固定参数

所有组复用同一镜像 ID、1017 权重、适配源码指纹和冻结输入。固定 TP4 / DP2 / EP8、全局 `max-seqs=256`、DSpark k5、OMP 8、EPLB、custom AG/RS、stacked-kv、bounded-prefill、FP8 KV；关闭 prefill throttle、decode-metadata、ragged-reuse，`logits-row-chunk=0`。多模态分块开启，每请求 64 张图片、2 个视频，每视频最多 32 帧、目标 1 FPS。Responses store 开启且只有一个 API server。

本轮 11 个负载单元的结果支持保留 16K 和 32K 两个 chunk 候选，不能替代完整 ISL / OSL 矩阵。主矩阵先固定 16K；32K 对照单独改变 chunk，使用相同 42 点、相同 payload 与重复次数。32K 关闭多模态分块的结果保留为已完成的兼容与性能参照。

| 轴 | 取值 |
|---|---|
| 最大上下文 | 1048576、524288、262144 |
| 显存水位 | 0.90、0.93、0.96 |
| 主矩阵组数 | 9，1M / 0.90 基准计入其中 |

先验证 0.96 在三个上下文长度的实际负载。如果出现启动或显存稳定性问题，保留失败组，按 0.01 步长寻找三个上下文共同稳定的上限，再取 `0.90 / 中点 / 共同上限`；最终矩阵须在结果中明确，不能把失败组删除或当作未执行。

## 受控测量

所有矩阵点、短性能、单请求 prefill、工具历史及图文混合各正式测量 3 次，报告中位数和最小至最大值。超长 C4 / C16 容量、300 秒混合、功能和 PPL 每组各一次；这些次数对所有组相同。预热与正式结果分开。

先执行 C256 通用预热；每个性能单元至少两轮 C2 预热，输入长度保持原形状，预热输出最多 128 token。通过实际 `engine=0/1` 的输入和生成 token 计数增长确认两个 DP 实例均工作。图文预热使用最大 4 图输入，覆盖全部图像媒体。未能证明预热完成时不能进入正式测量。

每个性能单元、重复轮和请求使用独立的合法缓存盐，组间重放同一 payload。冷 KV 必须逐请求观测到 `cached_tokens=0`。视觉编码缓存与 KV 分开描述：复用已校验的媒体并预热，保留采样计数，不把冷 KV 当作冷编码器。视频历史及 Responses 协议续轮保留其正常历史/缓存行为，单独标明。

原 300 秒 mixed 是闭环负载，请求数随处理速度变化。本次另用明确标记的 `fixed_arrival_schedule` 执行变体：5 批各 64 个 decode 请求，分别在 0 / 60 / 120 / 180 / 240 秒提交；15 个 prefill 请求每 20 秒提交一次。保留 C64 / C2 在途上限、原输入输出长度和 300 秒到达窗口。所有组共 335 个相同请求；记录提交等待、从计划到达到首 token/完成的延迟及排空时间。结果不与历史闭环 TPS 直接计算提升比例。

PPL 使用冻结的 272936 token、134 个非重叠 2048-token 窗口，`echo`、`top_k=1`、seed 1017；输入文本哈希与历史一致。每窗保存原始请求/响应和 logprobs，缺失/非零缓存或错误长度单独记为失败。GPQA 使用服务器安装的 bidevs，198 题、单轮、batch 32、temperature 0、top_p 0.95、输出预算 65536、reasoning effort max；工具版本与历史版本差异会记录。

## 历史证据的使用

| 项目 | 本次处理 |
|---|---|
| OMP 8、EPLB、custom AG/RS、stacked-kv、bounded-prefill | 沿用既定选择，固定参数；历史百分比只对应原硬件、代码、输入和缓存条件 |
| 旧 16K / 32K 排除结果 | 不作为当前配置优劣依据，使用完整受控对照 |
| 旧 0.90 / 0.95 对照 | 原输入 seed 不同，不据此预判高水位必然较慢；由本次矩阵判断 |
| prefill throttle | 本次主矩阵固定关闭；需要重启该候选时再单独比较，不夹入上下文/显存轴 |
| decode-metadata + ragged-reuse、logits-row-chunk、TP8 | 保留历史未采用结论及其条件，未改动时不重开参数轴 |
| adaptive DSpark、CPU offload connector、compact MQA | 保留失败证据和排除状态 |
| 既有视觉 / Responses GPU 验收 | 保留正式记录；本次各组仍执行适用功能验收和 PPL |

## 执行与证据

配置为 [`profile_matrix.json`](../config/benchmarks/profile_matrix.json)，逐组执行入口为 [`profile_matrix.py`](../scripts/benchmarks/profile_matrix.py)，服务切换入口为 [`profile_campaign.py`](../scripts/benchmarks/profile_campaign.py)。冻结数据、逐组启动回执、代码/镜像身份、原始结果、完整服务日志和采样 metrics 保存于服务器 `/tmp/dsv41-profile-20261025/`，本地归档位于 `runtime/profiling-20261025/`。

每组记录实际 KV 容量，输入/输出/总 token 吞吐、TTFT / TPOT / 端到端延迟及分位数、输入输出长度、成功率、缓存命中、等待队列、抢占/重计算和 OOM/服务异常。不存在的运行时指标标为未提供，不推断为零。相同 case、相同输入和测量条件才计算变化，不把不同工作负载的 TPS 平均成综合分数。

失败和重试使用独立 attempt 目录；阶段完成只表示该阶段，不代表九组及 GPQA/soak 全部完成。最终报告必须核对全部预期组合和一次性项目的真实回执，再给出分场景推荐配置。
